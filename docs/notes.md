# Как собран этот проект

Проект склеен из трёх архивов, сделанных на разных машинах, плюс приведён
в порядок под публикацию.

## Что было в архивах

| Файл | `11_pycades` | `11_pycades_` | `11_pycades____` |
|---|---|---|---|
| `Dockerfile` | есть | идентичен | идентичен (без `WORKDIR /app`) |
| `CMakeLists.txt` | есть | идентичен | идентичен |
| `sources.list` | есть | идентичен | идентичен |
| `compose.yml` | есть | идентичен | volume закомментирован |
| `app/` с кодом | **есть** | нет | нет |
| `команды крипто про.txt` | **есть** | есть | нет |
| `ссылки GIT.txt` | **есть** | нет | нет |
| `pycades.so` | нет | нет | **есть** (x86-64, 30.08.2025) |
| `.vscode/settings.json` | нет | нет | есть (`D:/Docker/11_pycades/pycades`) |

Второй архив — полное подмножество первого. Уникального содержимого в нём нет.
Из третьего уникален только собранный `pycades.so`.

Базой взят первый архив. Собранный `.so` в репозиторий не включён: он собран
под Python 3.11 и конкретную версию `cprocsp-pki-cades`, а в образе всё равно
пересобирается с нуля.

## Что исправлено

### Сборка была привязана к плавающему `main`

Старый `Dockerfile` делал `git clone https://github.com/CryptoPro/pycades.git`
без указания версии. 17 марта 2026 года upstream отрефакторил репозиторий:

* исходники переехали в `src/pycades/`;
* `arm64_support.patch` удалён;
* `errormsg.cpp` удалён;
* появились `Makefile`, `pyproject.toml`, сборка через `cmake -S . -B build`.

После этого старый рецепт перестал собираться: шаг `patch < ./arm64_support.patch`
падает, а подменный `CMakeLists.txt` перечисляет файлы, которых в корне больше нет.

Теперь версия зафиксирована тегом (`PYCADES_REF=v0.1.70300`).

### Подменный `CMakeLists.txt` оказался лишним

Сравнение с upstream показало, что на коммите `77f2ab0` (15.08.2025 — как раз
время исходной сборки) родной `CMakeLists.txt` уже содержал
`SET(Python_INCLUDE_DIR "/usr/include/python3.11")`, а единственное отличие
самодельного файла — определения

```
-DLINUX -DPROC_TYPE_ARM64=7 -DPROCESSOR_TYPE=PROC_TYPE_ARM64
```

то есть ровно то, что добавляет `arm64_support.patch`. В старом `Dockerfile`
патч применялся, а следом `COPY` затирал результат тем же самым содержимым —
один из двух шагов был лишним.

Ни патч, ни подмена больше не нужны: в новом upstream эти определения
включаются автоматически и только на arm64. Поэтому самодельный
`CMakeLists.txt` из архивов в проект не перенесён.

Если когда-нибудь понадобится вернуться к старому рецепту (Ubuntu 23.10,
Python 3.11), достаточно взять коммит `77f2ab0`, применить лежащий в нём
`arm64_support.patch` и подложить `sources.list` с зеркалом
`old-releases.ubuntu.com` — mantic снят с поддержки, штатные зеркала отдают 404.

### Установка КриптоПро перестала зависеть от номера версии

Было прибито гвоздями:

```dockerfile
apt install -y ./cprocsp-pki-cades-64_2.0.15000-1_amd64.deb
apt install -y ./cprocsp-pki-phpcades_2.0.15000-1_all.deb
```

Стало — `scripts/install-csp.sh`, который ищет пакеты по маскам и молча
пропускает отсутствующие. Обновили дистрибутив — рецепт не сломался.

Пакет `cprocsp-pki-phpcades` из установки убран: он нужен для PHP, к pycades
отношения не имеет.

### Секреты вынесены из кода

В `main.py` были зашиты отпечаток сертификата и пин-код контейнера,
в `команды крипто про.txt` — второй пин и имя боевого контейнера с ФИО.
Всё это переехало в `.env` (не коммитится), в шпаргалке оставлены плейсхолдеры.

**Если эти пин-коды использовались на реальных контейнерах — их стоит сменить.**

Из `app/` убраны файлы подписанной доверенности (`.xml` и `.sgn`) — это настоящая МЧД
с данными организации, ей не место в публичном репозитории. Вместо неё
`samples/sample.xml`.

### Прочее

* `response.jpg` и `test_image.jpg` — байт в байт один файл, оставлен один.
* Контейнер `keys/test1.000` просрочен 03.01.2026, поэтому добавлен флаг
  `SETUP_TEST_CERT`: он ставит тестовую связку `pycades-root` / `pycades-test`
  из фикстур `tests/fixtures` в исходниках pycades (действует до 2050).
  Фикстуры не копируются в репозиторий — они берутся из `/usr/src/pycades`
  внутри образа, поэтому этот каталог в `Dockerfile` намеренно не удаляется.
* `cryptopro.py` и `algorithm.py` — дословная копия
  [volstr/cryptopro](https://github.com/volstr/cryptopro) (MIT). Оформлены как
  vendored-пакет `app/vendor/cryptopro/` с приложенной лицензией.
* Из `compose.yml` убран устаревший ключ `version:`.
* Демо-ручки `/get_id`, `/get_file`, `/download_binary` перенесены в `/demo/*`.
* Старый `POST /sign-xml/` оставлен как deprecated-алиас, чтобы уже написанные
  вызовы из 1С продолжали работать.
