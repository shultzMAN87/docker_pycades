# Ключевые контейнеры

Каталоги вида `<имя>.000` из этого каталога `entrypoint.sh` копирует при старте
контейнера в `/var/opt/cprocsp/keys/<пользователь>/` и выставляет права 700/600.

## test1.000 — демонстрационный контейнер

Лежит в репозитории намеренно, чтобы проект можно было запустить и проверить
сразу после клонирования.

* издатель: тестовый УЦ EasyCert (`noreply@test.ru`, `fake.testkontur.ru`);
* имя контейнера: `TEST 2024-10-03T14:16:25 a79c8399efbc4bd4ae87bbb24faa8848`;
* **сертификат просрочен 03.01.2026.**

**Подписать им нельзя** — КриптоПро вернёт `0x800B0101` (`CERT_E_EXPIRED`).
Флаг `CHECK_CERTIFICATE=false` тут не спасает: он отключает проверку цепочки
и отзыва, но не срока действия. Контейнер оставлен как пример структуры
каталога и для проверки того, что CSP вообще видит ключи.

Чтобы получить рабочий сертификат для тестов, проще всего поставить
`SETUP_TEST_CERT=true` в `.env` — тогда при старте импортируется тестовая
связка из фикстур pycades, действующая до 2050 года. Подробнее — раздел
«Тестовый сертификат» в README.

## Свои контейнеры

Положите каталог `<имя>.000` рядом и перезапустите сервис:

```bash
cp -r /путь/до/mycontainer.000 keys/
docker compose restart
docker compose exec pycades certmgr -list
```

**Реальные контейнеры в git не коммитятся** — в `.gitignore` есть правило
`keys/*.000/` с исключением только для `test1.000`. Пин-код от контейнера
задаётся через `CERT_PIN` в `.env`.

## PFX

Файлы `.pfx` и `.p12`, положенные в этот каталог, `entrypoint.sh` импортирует
при старте командой `certmgr -install -pfx` — конвертировать их в каталог
`*.000` заранее не нужно, контейнер создаст сам КриптоПро.

Пароль от файла задаётся переменной `PFX_PASSWORD`, пин создаваемого
контейнера — `CERT_PIN`. Импорт идемпотентный: файл, уже импортированный
в этом экземпляре контейнера, при перезапуске пропускается (отметки лежат
в `/var/lib/pycades/imported`).

Каталоги `*.000` и файлы `*.pfx` можно держать здесь одновременно.

Такие файлы в git не попадают: `.gitignore` закрывает `*.pfx` и `*.p12`.
